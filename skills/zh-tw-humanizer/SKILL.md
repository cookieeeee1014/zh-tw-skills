# 繁體中文去 AI 味

這是兩個不同的問題，必須分開處理：

1. **這是不是台灣／香港的繁體中文**——地區用詞問題
2. **這像不像人寫的**——AI 腔問題

一篇用詞完全正確的繁體中文，讀起來照樣可以是 AI 寫的。反過來說，一篇口語自然的文章，只要出現一個「軟件」就露餡。**先修第一個，因為它是一票否決。**

---

# 問題一：繁簡判定

## 四層，從工具能解決到不能

| 層 | 內容 | 例子 | OpenCC 能處理嗎 | AI 常犯嗎 |
| --- | --- | --- | --- | --- |
| L0 | 字形 | 汉→漢、体→體 | ✅ 能 | 很少（模型通常會轉） |
| **L1** | **術語／命名** | **信息→資訊、软件→軟體** | **❌ 不能** | **極常犯** |
| L2 | 構詞法 | 進行討論→討論 | ❌ 不能 | 常犯 |
| L3 | 語用／語體 | 公文腔、稱謂 | ❌ 不能 | 常見 |

**關鍵在 L1。** OpenCC 把「信息」轉成繁體，結果還是「信息」——字形 100% 正確，用詞 100% 是大陸的。這就是 AI 版繁體最刺眼的破綻，而且**任何繁簡轉換工具都救不了**。

## 置信度分級

不要把所有詞一視同仁。台灣、香港用詞不完全一致，有些詞兩地通用，有些專業語境可保留。

檢查器內含**教育部《國語辭典簡編本》附錄「兩岸常用詞語對照表」**（620 條），這是官方資料，優先採用。它涵蓋的是生活與通用詞彙——`公尺←米`、`埠←端口`、`網際網路←互聯網`、`OK繃←創可貼`、`點滴←吊瓶`、`拘提←拘傳`。

官方表沒收的 **IT 術語**由下列人工詞表補足，這是兩者互補的關係。

**A 級：台灣與香港都不這樣說，直接改**

信息→資訊、軟件→軟體、硬件→硬體、網絡→網路、內存→記憶體、默認→預設、加載→載入、屏幕→螢幕、打印→列印、源代碼→原始碼、服務器→伺服器、賬號→帳號

**B 級：多數情況該改，但特定領域可保留**

| 詞 | 建議 | 保留條件 |
| --- | --- | --- |
| 數據 | 資料 | 統計、資料科學語境「數據」也通用 |
| 用戶 | 使用者 | B2B 產品語境可用「用戶」 |
| 質量 | 品質 | 物理學語境「質量」才正確 |
| 優化 | 最佳化／改善 | 技術文件「最佳化」較精確 |
| 文件 | 檔案 | 電腦檔案用「檔案」，公文用「文件」 |
| 支持 | 支援 | 技術語境用「支援」 |

**C 級：地域分歧，看目標讀者**

| 台灣 | 香港 | 說明 |
| --- | --- | --- |
| 品質 | 質素 | 香港用「質素」 |
| 網路 | 網絡（香港也用「網絡」） | 香港「網絡」不算錯 |

**所以要先問：讀者是台灣還是香港？** 不確定就採台灣用法。

## 單字詞：不檢測

官方表裡有 11 個單字詞（0.8%），工具**完全不做檢測**。

理由：中文沒有詞邊界。官方表收「公尺←米」指的是長度單位，但「米飯」「玉米」「稻米」的「米」是 rice；「進行」的「行」也不是任何單位。字串層面分不出來，任何一邊的判定都會錯。

這 11 個字由人自己看上下文。工具不猜。

## L2 構詞法：大陸的雙音節膨脹

大陸書面語傾向把動詞名詞化、加虛詞拉長。這是語法習慣，不是單詞，要靠句型判斷。

| 病灶 | 改法 |
| --- | --- |
| 進行討論／進行分析 | 討論／分析 |
| 作出決定／作出回應 | 決定／回應 |
| 對於…而言 | 對…來說 |
| 在…方面上 | …的部分／就…而言 |
| 通過…來… | 用…來…／直接說 |
| 一個重要的問題 | 重要的問題（刪「一個」） |

## L3 語用

- 大陸公文腔：「關於…的通知」「現將…如下」→ 台灣少用
- 稱謂：台灣書面語「您」的密度低於大陸
- 省略主語的習慣不同

# 問題二：AI 腔

## 原理：為誰而寫

模型寫作時選的是**對最廣泛讀者都成立**的表達——所以處處安全、處處平滑。人寫作只對**一個具體讀者**說話，因此會有跳躍、省略、忽然短一句。

推論出一條硬規則：**保留的每一句，都必須給讀者一個原本沒有的資訊。** 做不到的句子就刪。這一條砍掉的廢話比所有詞表加起來都多。

## 證據強度：不要看到就改

不同破綻的可信度差很多。原則：**破綻的權重等於「細心作者刻意這麼寫的頻率」——越少見越可信。**

**單獨出現就足以判定：**

- 「不是 X，而是 Y」的否定平行
- 「首先…其次…最後」（在非技術文件裡）
- 「作為一個 AI」「我理解你的需求」
- A 級大陸用詞

**要成群才算（單個不算）：**

- 破折號 —— 很多編輯也用，單個不算
- 高級同義詞 —— 正式文體本來就會用
- 過渡詞（因此、然而、此外）—— 人類也這樣寫
- **模糊限定（可能、或許、通常）—— 這是人寫作的標誌，不是 AI 的**

## 六個方向

| 方向 | 表現 | 中文例子 |
| --- | --- | --- |
| 鋪陳而非陳述 | 句子標示重要性卻不加事實 | 「這不僅是 X，更是 Y」 |
| 按規則的節奏 | 三件套、破折號到處用 | 「首先…其次…最後」 |
| 膨脹 | 普通事實包裝成關鍵 | 「具有重要的意義」「標誌著里程碑」 |
| 迴避簡單詞 | 用高級同義詞 | 撰寫←寫、運用←用、具備←有 |
| 迴避「是」 | 迂迴說法 | 「扮演著…的角色」「起到…的作用」 |
| 格式當裝飾 | 加粗、標題化 | 每一項都加粗 |

## 三個可量測的信號

| 信號 | 怎麼測 | AI | 人 |
| --- | --- | --- | --- |
| 句長均勻 | 句長標準差 ÷ 平均句長 | < 0.35 | > 0.5 |
| 抽象詞密度 | 賦能/閉環/落地 ÷ 千字 | 高 | 低 |
| 高級同義詞密度 | 撰寫/運用/具備 ÷ 千字 | 高 | 低 |

實測同一主題：AI 寫的節奏 0.349，手寫的 0.82，差 2.35 倍。

## 操作順序：先刪 → 再具體 → 最後調節奏

**不能顛倒。** 先調節奏只會得到「比較有變化的廢話」。

1. **刪**：模板句整句刪掉比改寫好。標準是每一句都要說出一件具體的事。
2. **具體化**：「提升效率」→「40 分鐘縮到 5 分鐘」；「優化體驗」→「少點兩次、少填三個欄位」。
3. **調節奏**：長句後來一句短的。判斷標準是**讀出聲**——每句都一樣長就是 AI。

## 語氣層的具體病灶

- **假謙虛**：「作為一個 AI」「我理解你的需求」→ 直接給答案
- **過度熱情**：「讓我們一起來探索」→ 講要做什麼
- **無出處權威**：「研究表明」「根據統計」→ 給來源或刪掉
- **過度確定**：「毫無疑問」「毋庸置疑」→ 拿掉
- **討好開場**：「這是個很好的問題」→ 刪

# 人的寫作長什麼樣

維基百科《Signs of AI writing》有一節專門列「**人類比 AI 更常使用**」的句式。改寫時要把這些**加回去**，不是刪掉：

- 簡單的「是」「有」（AI 傾向迴避，改用迂迴說法）
- 樸素動詞：寫（非撰寫）、用（非運用）、試（非嘗試）、過世（非逝世）
- 最高級與絕對陳述：「最好的之一」「唯一」「第一個」
- 限定詞與強調詞：**或許、通常、非常**
- 具體、不尋常的細節：真實地址、奇怪引述
- 混合情緒與未解決的張力
- 帶年代感的用語：俚語、梗
- 真誠的旁白與自我糾正：（我這裡一直想說「幾乎」，但其實是確定）

**去破綻只是一半工作；結果還得像個人。**

---

# 不要當成 AI 標誌的事

維基把這些列為 **ineffective indicators**（不可靠），用了會誤判：

- 文法完美
- 正式／學術腔（要看具體用詞，不是整體風格）
- 文白夾雜
- 沒有引用來源
- 單獨出現的過渡詞
- 單獨出現的模糊限定詞

**而且：靠感覺判斷的人，準確率不比隨機猜好多少**（Cheng et al. 2025）。所以要看具體字串，不要憑「讀起來怪」。

# 不要過度矯正

| 情況 | 保留 |
| --- | --- |
| 技術文件、法律文件、操作步驟 | 「首先」「其次」是正確結構 |
| 物理語境 | 「質量」正確 |
| B2B 產品 | 「用戶」可接受 |
| 正式文書 | 該有的禮貌不要刪光 |
| 香港讀者 | 「質素」「網絡」不算錯 |

**判斷法**：這個詞／句式是**為了表達精確**，還是**為了填滿篇幅**？前者留，後者砍。

# 輸出方式

改寫時給兩段：

1. 改寫後的全文
2. 變更清單，按 L1／L2／L3／AI 腔分類，說明改了什麼、為什麼

不要逐句對照，讀者要結果不要過程。

# 接上檢查器

`scripts/check.py --prompt` 會把**原文、檢測到的每一個問題、上面那四步規則、該豁免的地方**組成一份完整的改寫請求。把它整份餵給任何模型（或直接當成本 skill 的輸入）就能開始改：

```bash
python scripts/check.py --prompt 文章.txt > 改寫請求.md
```

這樣檢測結果和改寫規則不會脫節——模型看得到「第 3 行第 43 字『質量』→ 品質」這種具體位置，而不是只有抽象的「去 AI 味」。
